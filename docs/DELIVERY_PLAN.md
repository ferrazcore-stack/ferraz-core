# FERRAZ — Plano de Entrega

## Estimativa realista

A construção será incremental. Não é seguro prometer que o produto completo estará pronto em poucas horas, porque além do código precisamos validar banco, permissões, documentos, integrações e o fluxo real.

### Hoje — Fundação + primeira interface
- arquitetura do CORE;
- domínio;
- backlog;
- contrato de multiempresa;
- base visual;
- especificação do Dashboard;
- estrutura inicial do produto operacional.

### Próximo ciclo — Núcleo comercial
- Dashboard funcional;
- Clientes;
- Obras;
- Profissionais;
- Orçamento;
- Opções;
- Aprovação;
- Pedido;
- PDF inicial.

### Ciclo seguinte — Operação técnica
- Medição;
- Liberação Técnica;
- Desenho;
- Paginação;
- Peças;
- Produção;
- Conferência.

### Ciclo seguinte — Logística + gestão
- Carregamento;
- Romaneio;
- Entrega;
- Instalação;
- Termo/Recibo;
- Financeiro;
- Comissões;
- Indicadores.

### Finalização — Qualidade e produção
- testes completos;
- isolamento de tenants;
- segurança;
- documentos;
- observabilidade;
- performance;
- backup/recuperação;
- deploy;
- validação com uma obra real.

## Critério de conclusão

Uma fase só é considerada finalizada quando estiver implementada, integrada ao domínio, testada e documentada. Uma tela isolada ou um mock visual não conta como módulo concluído.

## Comunicação

Quando uma fase estiver tecnicamente concluída, o progresso será registrado no repositório e comunicado na conversa. Não haverá promessa de execução em segundo plano: as alterações são feitas durante as sessões de trabalho.
